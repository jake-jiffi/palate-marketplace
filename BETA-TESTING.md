# Palate 2.1.0-beta.1, tester track

Palate 2.0.0 shipped on 4 October 2026: the live-design builder that ran here as 1.18.0-beta.1 to beta.9 is now the customer plugin, `palate-website-builder`, and the 1.16 builder stays installable as `palate-classic`.

This beta currently equals 2.0.0. New experiments land here first, and this page will say what each one changes. Until then there is no reason to run the beta instead of 2.0.

The 1.18 beta notes (critic and builder rounds, Higgsfield media, one design system per site, film scope, terminal install, the beta.9 fixes) are now the 2.0.0 entry in the plugin's CHANGELOG.

## Known limitations

- Design speed and consistent visual quality are not yet established. Earlier comparison runs missed timing and visual targets. A subsequent raw test improved visually but still contained motion and product-accuracy defects despite passing its own checks. This release has not yet been tested in a fresh complete website build.
- Complete end-to-end workflows across Codex and Claude remain unvalidated, including the full website/brand/blank-input matrix, selection and resumption, and deployment.
- Shopify checkout, remote cart persistence and recovery are experimental in this release. Earlier development-store checks do not certify a site generated by this frozen candidate.
- Host permissions can interrupt local preview startup. One observed port error recovered after the host retried with the required permission. Large collections of installed skills can also exceed a host's context budget.

Beta.3 passed local instruction and package checks, plus a four-case agent instruction simulation covering autonomous escalation, the shared round allowance, review-only scope and stopping after repeated lack of improvement. Earlier beta.1 checks covered packaging, manifests, installation and local preview startup. No full website end-to-end test was run for beta.3 or beta.4. These checks do not establish design quality or a complete working customer website. No claim is made that the beta outperforms plain Codex or Claude.

Use a disposable local project and keep backups. Review generated code and content before deployment. Test commerce with a development store, without placing real orders. Keep private brand documents and credentials out of public previews and feedback attachments.

## Install

Install only one Palate plugin at a time. Remove the production plugin or any local candidate installation before installing this beta. Leave unrelated plugins alone.

In your terminal (these work for Claude Code in the terminal, an IDE or the desktop app; the `/plugin` chat commands only run in the terminal version), add the marketplace if it is not already configured:

```sh
claude plugin marketplace add jake-jiffi/palate-marketplace
```

For an existing marketplace, refresh it:

```sh
claude plugin marketplace update palate
```

Then install:

```sh
claude plugin install palate-beta@palate
```

If `palate-beta@palate` is already installed, run `claude plugin update palate-beta@palate` after refreshing the marketplace. Either way, fully quit and reopen Claude Code (in the desktop app, start a new session) so the plugin loads.

In Codex, add the marketplace if needed, then install:

```sh
codex plugin marketplace add https://github.com/jake-jiffi/palate-marketplace.git
codex plugin add palate-beta@palate
```

If it is already configured, refresh it with `codex plugin marketplace upgrade palate` before installing. Start a fresh Codex session after installation. Confirm that `palate-beta@palate` is the only enabled Palate plugin and its version is `2.1.0-beta.1`.

Use your existing Palate MCP connection, or follow its authentication prompt. Start the builder with `/palate-beta:palate-website-builder` in Claude or `$palate-beta:palate-website-builder` in Codex. Provide the website or brand material you have and describe what visitors should be able to do.

## Feedback and recovery

Send Jake the host and plugin versions, starting material type, time to the first useful preview, steps to reproduce any failure, and a screenshot or short motion recording. Describe which design you preferred and why. Redact private documents, customer details, tokens and passwords.

To leave the beta, uninstall `palate-beta@palate`, install `palate-website-builder@palate`, and start a fresh host session. This restores the production plugin for supported production projects. It does not migrate new beta projects into the older production workflow. Keep new beta projects backed up and use their bundled runtime when continuing them.
