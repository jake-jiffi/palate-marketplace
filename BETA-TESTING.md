# Palate 1.18.0-beta.1, tester release

This is an opt-in release for a small tester group, published on 14 September 2026. Features are frozen so we can collect feedback from real use. The production plugin remains at 1.16.0.

The beta introduces working Astro design options, motion as part of the ordinary design experience, and reference research through the Palate MCP. You can start with an existing website, brand material, a written brief, or no material and a short intake conversation. Shopify is an optional path for appropriate ecommerce projects, especially existing Shopify stores.

## Known limitations

- Design speed and consistent visual quality are not yet established. Earlier comparison runs missed timing and visual targets. The latest run was stopped to limit credit usage before it produced an independently accepted option.
- Complete end-to-end workflows across Codex and Claude remain unvalidated, including the full website/brand/blank-input matrix, selection and resumption, and deployment.
- Shopify checkout, remote cart persistence and recovery are experimental in this release. Earlier development-store checks do not certify a site generated by this frozen candidate.
- Host permissions can interrupt local preview startup. One observed port error recovered after the host retried with the required permission. Large collections of installed skills can also exceed a host's context budget.

Packaging, manifests, installation and local preview startup are the release checks for this tester build. Earlier focused routing and MCP research checks passed. These checks do not establish design quality or a complete working customer website. No claim is made that the beta outperforms plain Codex or Claude.

Use a disposable local project and keep backups. Review generated code and content before deployment. Test commerce with a development store, without placing real orders. Keep private brand documents and credentials out of public previews and feedback attachments.

## Install

Install only one Palate plugin at a time. Remove the production plugin or any local candidate installation before installing this beta. Leave unrelated plugins alone.

In Claude Code, add the marketplace if it is not already configured:

```text
/plugin marketplace add jake-jiffi/palate-marketplace
```

For an existing marketplace, refresh it:

```text
/plugin marketplace update palate
```

Then install and reload:

```text
/plugin install palate-beta@palate
/reload-plugins
```

If `palate-beta@palate` is already installed, use `/plugin update palate-beta@palate` after refreshing the marketplace, then reload.

In Codex, add the marketplace if needed, then install:

```sh
codex plugin marketplace add https://github.com/jake-jiffi/palate-marketplace.git
codex plugin add palate-beta@palate
```

If it is already configured, refresh it with `codex plugin marketplace upgrade palate` before installing. Start a fresh Codex session after installation. Confirm that `palate-beta@palate` is the only enabled Palate plugin and its version is `1.18.0-beta.1`.

Use your existing Palate MCP connection, or follow its authentication prompt. Start the builder with `/palate-beta:palate-website-builder` in Claude or `$palate-beta:palate-website-builder` in Codex. Provide the website or brand material you have and describe what visitors should be able to do.

## Feedback and recovery

Send Jake the host and plugin versions, starting material type, time to the first useful preview, steps to reproduce any failure, and a screenshot or short motion recording. Describe which design you preferred and why. Redact private documents, customer details, tokens and passwords.

To leave the beta, uninstall `palate-beta@palate`, install `palate-website-builder@palate`, and start a fresh host session. This restores the production plugin for supported production projects. It does not migrate new beta projects into the older production workflow. Keep new beta projects backed up and use their bundled runtime when continuing them.
